# ДЗ 3. Обучение ранжированию

Решение домашнего задания по обучению ранжированию на данных VK MARCO (HSE IR, осень 2026).

Обучил модель на готовых признаках и побил бейзлайн: 0.61922 → 0.62478 nDCG@10 на
отложенных запросах. Модель — CatBoostRanker с функцией потерь YetiRank, к 67 исходным
признакам добавил производные, нормированные внутри запроса.

- **Ник на Kaggle:** librust

## Что я сделал

Взял `CatBoostRanker` с `YetiRank` и добавил к 67 исходным признакам производные,
посчитанные внутри каждого запроса (по группе `QueryId`).

**z-нормировка 16 признаков совпадения** — `bm25f`, `bm25_*`, `coverage_*`, `lm_*`,
`tf_sum_*`. Масштаб BM25 и языковых моделей сильно гуляет от запроса к запросу, а
бустинг строит общие пороги сразу для всех запросов. Нормировка на среднее и стандартное
отклонение внутри запроса выравнивает шкалу. Это была подсказка в условии, и она
действительно сработала.

**log1p + z-нормировка 26 неотрицательных признаков** с тяжёлым правым хвостом — длины,
счётчики, BM25, `domain_docs`. Логарифм сжимает выбросы, и после него z-нормировка
описывает форму распределения, а не пару аномальных документов. Это дало ещё немного
сверх обычной z-нормировки.

**600 итераций с lr 0.05** вместо 200 с lr 0.1. С 200 итерациями на `YetiRank` модель
просто недообучена — это видно по валидации.

## Результаты

nDCG@10 на запросах, которые не участвовали в обучении. Считал на трёх независимых
разбиениях 80/20 (seed 1, 2, 42) и усреднил, потому что на одном разбиении разница
в пределах шума.

| Модель | nDCG@10 |
|---|---|
| Бейзлайн (`YetiRank`, 200 итераций, параметры по умолчанию) | 0.61922 |
| Моё решение | **0.62478** |

Прирост +0.0056, и он положительный на каждом разбиении: +0.0052, +0.0067, +0.0048.

Про значимость скажу честно: парное сравнение по 4200 запросам даёт +0.00158 на запрос,
95% бутстрэп-интервал [−0.00006, +0.00327]. То есть прирост небольшой и на грани
значимости. Он воспроизводится на всех разбиениях и согласуется с подсказкой из условия,
но по одному разбиению его от шума не отличить.

Кривая обучения растёт с объёмом данных, а финальная модель учится на всех 7000 запросах:

| Обучающих запросов | nDCG@10 |
|---|---|
| 2240 (40%) | 0.62400 |
| 3360 (60%) | 0.62121 |
| 4480 (80%) | 0.62424 |
| 5600 (100% train part) | 0.62673 |

## Как запустить

```shell
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

Две команды из условия:

```shell
./solution.py --train --model_file=model.bin PATH-TO-DATA
./solution.py --model_file=model.bin --submission_file=submission.csv PATH-TO-DATA
```

`PATH-TO-DATA` — папка с `train.csv`, `test.csv`, `features.md` и
`sample_submission.csv` со вкладки Data соревнования.

Seed зафиксирован (`SEED = 42`), обучение детерминировано: два независимых запуска дают
побайтово идентичный `submission.csv`.

Замерял на 20 ядрах и 15.7 ГБ RAM, без GPU:

| | Значение | Лимит задания |
|---|---|---|
| Время обучения | 149 с | ≤ 30 мин |
| Пиковая память | 432 МБ | ≤ 8 ГБ |
| Время предсказания | 0.9 с | — |

## Ограничения задания

- Использовал только готовые признаки, никаких новых признаков из текстов документов и
  запросов, никаких внешних данных и разметки.
- `solution.py` читает только `train.csv` и `test.csv` из переданной папки.
- Все преобразования считаются по группе `QueryId` без использования меток и применяются
  одинаково к train и test, утечки оценок нет.
- Валидация всегда по запросам целиком, не по строкам.
- GPU не нужен, на Linux работает.

## Что пробовал и что не сработало

| Вариант | nDCG@10 | Итог |
|---|---|---|
| LightGBM LambdaRank (лучший из 80+ конфигураций) | 0.62664 | не лучше |
| LightGBM rank_xendcg | 0.62636 | не лучше |
| XGBoost rank:ndcg | 0.62014 | хуже |
| CatBoost LambdaMart / QuerySoftMax / PairLogit | 0.609–0.624 | `YetiRank` лучше |
| Стекинг CatBoost + LGBM + XGB по OOF-предсказаниям | 0.62460 | хуже одиночной |
| Ансамбль 5 моделей | 0.62641 | не лучше |
| Бэггинг 5 фолдов × 2 seed | 0.62582 | хуже одиночной |
| Ординарное разложение P(≥1) / P(≥2) / P(≥3) | 0.61624 | заметно хуже |
| Отбор признаков top-20…70 по важности | 0.621–0.624 | полный набор лучше |
| Нормировка всех 67 признаков (134–201 признак) | 0.62498 | разбавляет модель |
| Взаимодействия, softmax-доли, агрегаты по запросу | 0.623–0.625 | не помогают |

Вывод, к которому я пришёл: всё упирается в качество готовых признаков. Они уже содержат
ранги и отношения к максимуму внутри запроса, поэтому ни смена модели, ни ансамблирование,
ни дополнительные производные признаки не дают прироста сверх нормировки внутри запроса.
Ансамбли не помогли по понятной причине — все модели учатся на одних и тех же 67 признаках
и ошибаются почти одинаково, поэтому усреднение сглаживает как раз те различия, которые
важны для nDCG@10.
